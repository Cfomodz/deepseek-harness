# 2379 — 会话接近上下文窗口时，固定 maxTokens 输出预算使请求仅超出 91 token 即 CONTEXT_WINDOW_EXCEEDED，且无法自动恢复

## Verdict

**Mostly working-as-designed, with one genuine design gap.** Split into three claims:

1. **"llm-deepseek does not clamp `max_tokens` against the context window" — CONFIRMED, and it is a deliberate, documented decision** (`packages/llm/llm-deepseek/README.md:42` + Agent Note `.agents/notes/implemented/architecture/2026-07-30-adapter-owned-max-token-defaults.md:13,25,33`). The OP's first requested fix (clamp at serialization) is a **rejected design**, not a bug fix. The supported remedy is configuration: `llm-deepseek.maxTokens`.
2. **"The compaction pressure threshold ignores the output budget, so overflow can happen before compaction ever triggers" — CONFIRMED as a real gap** in `compaction-basic`. The threshold is `floor(contextWindow × thresholdRatio)` compared against **input-only** measured tokens; nothing subtracts the completion budget. With the shipped defaults this is not merely theoretical — the numbers collide exactly as the OP reports. The OP's second requested fix is legitimate and is the one worth taking upstream.
3. **"No automatic recovery" — INSUFFICIENT-DATA / partly REFUTED.** An automatic `CONTEXT_WINDOW_EXCEEDED` recovery path exists and is wired by default (`packages/compaction/compaction-basic/src/index.ts:179-222`), and the recovery summarization call cannot itself hit this overflow because it passes an explicit small `maxTokens`. I could not reproduce the OP's non-recovery and could not identify a code path that guarantees it with the OP's stated configuration.

## Root cause

`llm-deepseek` ships a fixed 256,000-token completion budget that is serialized verbatim (`serialize.ts:184`) and, by deliberate decision (`.agents/notes/implemented/architecture/2026-07-30-adapter-owned-max-token-defaults.md:25,33`), never reconciled with the model's context window — while `compaction-basic` computes its trigger point as `floor(contextWindow × 0.8)` (`config.ts:144`) against **input-only** token measurements (`token-meter/README.md:30`). With the shipped defaults the trigger point (800,000) sits *above* the real usable input ceiling (1,048,576 − 256,000 = 792,576), so the safety net is mathematically unreachable: every long session must hit `CONTEXT_WINDOW_EXCEEDED` before automatic pressure compaction can ever fire.

- compaction fires at `floor(1,000,000 × 0.8)` = **800,000** input tokens
- usable input capacity is 1,048,576 − 256,000 = **792,576** input tokens

Since 800,000 > 792,576, the automatic-compaction safety net is mathematically unreachable under the defaults: any long session must hit `CONTEXT_WINDOW_EXCEEDED` first. Neither existing Agent Note covers this, so the threshold should be computed against usable capacity (`contextWindow − output budget`). Until that lands, the equivalent configuration workaround is:

```yaml
- name: '@deepseek-ai/dsh-compaction-basic'
  config:
    thresholdRatio: 0.75    # 750,000 < 792,576, with headroom
```
